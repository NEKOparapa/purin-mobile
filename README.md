# Wintermute Mobile

Flutter 移动端打开即进入持久会话，连接后会同步后端的对话历史。左上角的小日历显示今天的日期，有未读通知时会亮起圆点。点「日程」查看当日通知和安排，点「对话」或使用系统返回即可接着聊天。聊天和日程页右上角的齿轮可直接打开设置。iOS 用户可以在设置的「通用」中打开「记忆」。聊天首页可以直接输入，或点「聊聊今天」「想想晚饭」开始起草。

## 连接和使用

“连接与采集”顶部的“外观”默认跟随系统，也可以固定为浅色或深色。选择保存在本机，尚未连接服务和离线时都能更改。

1. 打开后端的 HTTPS 管理面板，在「设备」点击「添加设备」。
2. 在手机端「设置 → 连接」点扫码图标，或粘贴完整配对链接。客户端会自动生成设备 ID，提交本机名称和平台，并把凭据写入 Android 安全存储或 iOS 钥匙串。
3. 在对话底部输入消息，点回形针可添加图片或文件，每条最多 4 个，单个最大 32 MiB。点麦克风开始录音，再点一次转成文字。可以编辑草稿，也可以只选附件，然后点向上箭头发送。上一条仍在运行时可继续补充。网络中断后，未确认送达的消息可按原消息 ID 手动重试。
4. 在“连接与采集”中按需开启以下开关。每个设备单独保存选择，首次均为关闭。离线记录会在应用回到前台并联网后按原事件 ID 和发生时间续传。关闭某一项会清除该项待发的记录。

- **记录前台应用活动**统一记录 Wintermute 的前后台和页面变化。在 Android 授予“使用情况访问权”后，同一开关也控制其他应用的前台使用时段。iOS 记录 Wintermute 自身的活动。
  Android 通过常驻通知显示采集状态。Wintermute 在后台时约每 2 秒读取系统的应用切换事件，切走后将上一款应用的名称、起止时间和整数秒时长作为 `mobile.app_usage` 感知事件上传到 `POST /v1/perceptions`，可在「历史记录 → 感知层」查看。断网会保留待发时段并重试；服务被停止后，再次打开 Wintermute 会读取系统仍保留的近期事件并补传。时段从开启并授权后算起。
- **定时采集位置**按 20 分钟周期采集系统定位，静止时也采样。断网后暂存本机，系统授权、省电和后台调度可能延迟投递。
- **定时采集网络**随位置记录 Wi-Fi 连接状态和名称，默认关闭。后端通过 Photon 解析首个位置及距上一有效位置至少 300 米的新位置。
- Android 的**采集前台应用截图**需要开启“记录前台应用活动”并确认系统屏幕共享。同一应用连续在前台满 10 分钟截一次，同一应用内换页面沿用计时。切换应用、锁屏或采样中断超过 45 秒后重新计时。离开应用时，截图随本次时段上传到感知层，离线可重试。iOS 的**定时截屏**按 1、5 或 15 分钟采样，默认 5 分钟。系统结束共享后，需要手动重新开启。客户端在收到入库回执后清理已上传的图片，关闭截图或切换设备会清理待传图片。
  Android 最多缓存 32 张，iOS 最多缓存 64 张。队列满后保留已有截图，等上传腾出空间后继续采集。

手机打开、回到前台及停留在前台期间都会从后端读取当前会话。对话中能看到其他设备发送的消息和主 Agent 对日程等后台通知的回复。后端清空后，下一次成功同步会清除对话中的历史消息。本机保留未确认送达的草稿供手动重试。

接口密钥和记忆整理计划可在后端管理面板的「模型密钥」和「模型记忆」中设置。

## 移动端连接器

「设置 → 连接器」按本机系统显示应用。Android 注册八项安卓连接器，iPhone 注册 Apple Calendar、Apple Contacts、Apple Health、Apple Music、Photos、Apple Reminders 和 iPhone Location。开关按服务地址、设备和平台保存，默认关闭。手机在前台执行已启用并获系统授权的工具。

iPhone 支持查询和新建日程、查询联系人、查找及本机预览照片、创建和完成待办、单次定位，以及 Apple Music 曲库搜索和播放控制（iOS 15 起）。照片查询按日期和媒体类型筛选，仅返回授权范围的元数据。健康功能按本地自然日汇总可读取的步数、睡眠及锻炼，分享前显示摘要、服务地址和确认按钮。仅应连接用于健康或健身分析的服务。

iOS 签名时为 Runner 的 App ID 启用 HealthKit，并在开发者账户的 App Services 中开启 MusicKit。健康、音乐、有限照片和有限联系人权限需在对应系统与账号下验证。首次授权由用户在 iPhone 上完成。

## 安卓连接器与移动端通知

在「设置 → 连接器」可以查看闹钟和计时器、使用时间、日历、通讯录、文件、位置、通知和短信。通过 HTTPS 或回环地址连接后，点卡片可以为当前设备连接单独启用或关闭。系统撤回权限后，可在卡片内重新授权。Agent 通过设备连接器调用，手机在前台领取请求，结果保存到发起调用的会话。

使用时间返回最近 1 至 7 个自然日的系统统计，位置返回一次定位和采样时间。日历支持按时间段读取和打开预填表单，闹钟与倒计时由系统时钟处理。文件访问限定在用户选中的目录，支持按名称筛选、本层浏览和分段读取 UTF-8 文本。通知只读当前通知栏，短信按关键词返回收发号码、时间和匹配片段。短信读取取决于系统和安装渠道允许的权限。

Android 和 iOS 的「日程」按日历选中的本地日期显示「当日通知」和「当日安排」。通知列出计划时间、目标设备和投递状态，点「显示全部」可查看当天其余通知。点开已投递到本设备的通知可阅读正文、标记已读并保存附件。未授予系统提醒权限时，可在「当日通知」点「获取通知权限」。

应用在前台同步后端通知。Android 获得权限后还会通过系统调度器在有网络时检查新通知（周期约 15 分钟起，受省电策略影响）。iOS 会在应用打开或回到前台同步时提供本地提醒。点击系统提醒会进入日程并打开对应通知。

## 开发运行

使用 Flutter 3.44.6、Dart 3.12.2 和仓库中的 `pubspec.lock`。

```sh
flutter pub get
flutter devices
flutter run -d <device-id>
flutter build apk --debug
```

Android 模拟器访问开发机服务可用 `http://10.0.2.2:<端口>`，也可用 `adb reverse tcp:<端口> tcp:<端口>` 后连接 `http://127.0.0.1:<端口>`。Android debug 构建允许局域网 HTTP，正式环境使用 HTTPS。调试 APK 位于 `build/app/outputs/flutter-apk/app-debug.apk`。

iOS 工程使用相同的 Flutter 界面与协议、Keychain 和局域网用途说明。用 macOS、Xcode 和 iOS 模拟器运行 `flutter build ios --simulator`，真机需配置签名。Windows 环境只能验证 Android 设备流程。

iOS 真机签名时将 Runner 和 WintermuteBroadcast 两个目标加入同一个 App Group（`group.dev.wintermute.wintermuteMobile.screenshots`）。旧版 iOS 的屏幕广播扩展使用该共享容器暂存截图，供主应用恢复运行时上传。

## 静态检查

服务地址必须填写根地址，不要附加 `/v1`；非根路径会在保存连接前被拒绝。后端的 Python 模块拆分不影响本端协议，本端不调用旧 `/v1/profile`。在相邻 Wintermute 后端仓库运行 `uv run python tools/check_clients.py`，会启动隔离的本机后端并通过 `tool/backend_smoke.dart` 验证实际网络客户端、共享对话历史、截图上传及提问回答，无需模拟器或模型密钥。

```sh
dart format --output=none --set-exit-if-changed lib
flutter analyze
```
